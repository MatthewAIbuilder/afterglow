# Afterglow (working title)

A premium, Apple-level mobile app for discovering live DJ and festival performances. It combines a TikTok-style feed of live-set clips, behavior-driven artist recommendations, festival lineups and an interactive "My Sound" artist bubble map. The long-term headline feature is a personalized festival schedule built from the user's taste.

Expo / React Native / TypeScript. Also read @AGENTS.md (Expo's own agent rules: use `npx expo install`, Expo Router, current SDK docs rather than memory).

- **Discover playback (Milestone 6.5)**: only the on-screen clip plays, and only while Discover is the visible screen and the app is in the foreground (another tab, a pushed page, or a backgrounded app pauses video and stage alike; coming back resumes unless you paused). Rules are pure in `features/discover/playback.ts` and tested. The feed only talks to `ClipPlayer` (still from the video while loading, fades into the player once it plays; picks the player per provider); YouTube details stay in `YouTubePlayer`/`youtube.ts`/`media.ts`, so a native video source can slot in later. A vertical swipe that starts on the video moves the feed (`feedPager.ts`). Optional vertical footage: `source.vertical: true` (official Shorts) gets a tall 9:16 player with the rail beside it (`videoLayout.ts`); no Shorts are in the feed yet. `ClipPlayer.onPlayed` reports only live, actually-playing seconds: any watch-time signal must use it and nothing else.
- **My Sound**: bubble map. Top match pinned at centre, others placed by sound direction and distance by match, label-aware collision (no overlaps), pan with momentum, pinch zoom, double-tap recenter, bubbles trail and wobble when panned, reshape animation when taste changes, glass artist sheet.
- **Festivals** tab, festival pages (lineup sorted For you / Billing, set times when published, optional lineup poster with full-screen zoom viewer).
- **Artist** pages: match, sound tags, where they play, clips (open in Discover), similar artists.
- **Taste engine** v1 and **persistent reactions** (AsyncStorage).
- **Watch behaviour (Milestone 7)**: how a real clip was watched is a quiet, passive taste signal. `features/taste/watch.ts` (pure) keeps one session per visit to a clip, fed only by `ClipPlayer.onPlayed` spans, and tracks *coverage* (merged parts of the clip), so repeated reports or seeking back never count the same seconds twice. On leaving the clip: ~all of it covered = `through`, a full pass plus half again = `replayed`, 1 to 4s played then swiped away = `quick`. Loading, hidden, background or stage-placeholder playback gives nothing; leaving Discover or opening the artist mid-clip excuses a short watch. Per clip the strongest watch is kept (through twice on separate visits = replayed; never beyond). Engine weights: through 0.3, replayed 0.5, quick -0.2 (like 1, save 1.3, skip -0.8); a skip cancels the watch on that clip, a like/save cancels a quick swipe, and all passive signal per artist is capped to [-0.3, 0.6], below one like or skip. Watches spill over to similar sounds like likes. My Sound's subtitle counts watched clips.
- **Discover feed ranking (Milestone 8)**: `features/recommend/feed.ts` (pure, deterministic, no randomness) orders the feed from the live taste (which already carries likes/saves/skips/watching and spill-over) plus what only the feed knows. Each artist is in one lane: `personal` (match >= 0.75), `explore` (below that, or unknown, but sound-similar >= 0.3 to one of your top 3 artists), `discover` (a different sound, or no signal at all; unknown artists first). Lanes take turns in a fixed pattern P P E P E D (empty explore turns fall back to personal). Every artist gets one clip before anyone's second, never the same artist twice in a row (feasibility guard at the tail). Blocks: fresh clips, then clips of artists you turned down (more skips than likes+saves), then clips seen in the last 6h (seen longest ago first), then skipped clips. Each item carries a `Reason`; `recommend/copy.ts` turns it into a quiet note after the match ("Close to ILLENIUM", "A different sound", "New to you"; strong matches get none). `useRankedFeed` keeps the clip on screen and the next one fixed and re-ranks the rest as you react. Viewing history (`state/seen.tsx`, clip -> last seen ms, bounded to 500) is marked when a clip is on screen while the feed is live; it never feeds the taste engine.
- **Festival discovery loop (Milestone 9)**: Discover is always focused on one festival (default: the first with clips) and only shows artists on its lineup. Its header ("Solstice 2026 ›", "Live sets from the lineup · dates") opens the festival page. Under each clip, the artist's place there (set time, or "On the lineup, set time to come") is a link to the festival page, with a small star if you starred them there. The artist button opens the artist in that festival's context (must-see star works). Festival pages have a "Discover the lineup" pill (`/?festival=<id>`) that refocuses Discover; jumping to a clip (`/?clip=<id>`) moves the focus if that artist doesn't play the current festival, and artist pages opened from a festival pass it along. Relationships are pure in `features/festivals/links.ts` (playsAt, lineupClips, defaultFocus, focusForClip, nextFocus, festivalLine, lineupReach) and tested.

## Product principles

- **Visual standard is non-negotiable**: Apple-level polish, dark-first, minimal and premium, excellent typography and spacing, smooth purposeful motion, tasteful blur/glass, strong but meaningful haptics. No generic dashboard look, no cheap neon "EDM app" look. The accent is one restrained purple glow ("festival light at night"). Artist imagery should eventually drive per-artist color.
- **The bubble map is the core differentiator.** Bubble size = predicted affinity. Similar sounds cluster naturally. It should feel like a living musical universe, not a chart.
- **Recommendations are behavior-driven.** Scores come from what the user does: likes, saves and skips, plus quieter watch behaviour (watched through, replayed, quick swipe away), all with spill-over to similar sounds; later follows and other meaningful signals. Passive signals must never outweigh explicit ones. Never replace this with arbitrary static scores. `data/mock/tasteProfile.ts` is only the starting prior.
- **Festivals have two phases.** Lineups are known months ahead; set times arrive a week or two before. Every schedule feature must work gracefully in both.
- Copy is plain, sentence case, user-facing (no developer language in the UI).

## Rules for changes

- Work in **small, testable milestones**. Propose the smallest next step before large changes. Stop after each milestone so the user can test on a real phone.
- **Never rebuild or redesign working features** unless explicitly asked. Extend, don't replace.
- No backend, auth, scraping, payments or AI services unless the user asks. (Music sign-in was asked for in Milestone 43; it stays on the device.)
- Music-library data is private: tokens only in the secure store, normalised data only in AsyncStorage, nothing logged, and anything a future profile shows goes through `shareableMusicProfile` with consent. Never commit client secrets, MusicKit keys or tokens; the app needs none.
- Add dependencies only with `npx expo install` and only if they run in Expo Go. The one exception is `expo-dev-client` (Milestone 44), which exists to make a development build; it doesn't change what runs in Expo Go. Because of `app.config.ts`, a package whose config plugin `npx expo install` would add must be added to `app.json`'s `plugins` by hand.
- Real data comes from the user, through the catalogue file (`catalogue/afterglow.json` or their hosted file), plus the one feed the user chose on 2026-09-30: EDMTrain's festival listings, imported automatically each night (Milestone 63, `docs/events-import.md`); hand-curated festivals always win over it. Discover clips also come automatically each night from YouTube search (the user chose "any channel" on 2026-09-30; Milestone 69). Never invent lineups, set times or video sources; enter only what the user provides, from official sources, or what these automatic feeds find. Don't add festival posters yourself (the user supplies links they have rights to). Artist photos come automatically from Deezer's public search (the user asked for photos from any free source on 2026-09-30; Milestone 66); a photo set in the catalogue wins. `npm test` must stay clean for `catalogue/afterglow.json`.
- Respect reduced motion (`useReducedMotion`) and accessibility labels.
- Everything must also work in a browser (the website): alerts and sheets only through `lib/dialog.ts`, sharing through `lib/share.ts`, and anything phone-only (files, Photos, secure store, notifications) behind a `.web.ts` file or a `Platform.OS === 'web'` check that says it's in the app.
